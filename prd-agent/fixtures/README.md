# fixtures 说明

回放样本。每份样本既是**评测输入**，也自带**期望输出**。

## 命名

`fixture-<编号>-<标签>.txt`，例如 `fixture-F1-feedback.txt`、`fixture-F3-contradict.txt`。

## 文件结构（沿用 AI-office-competitor-daily 的写法）

```
【合成样本 Fx 名称｜全部虚构】
fixture 名填：Fx-标签
期望：需求 N 条——{逐条写清编号、优先级、来源}；以下内容应被过滤：{...}

========== source 从下一行开始复制 ==========
（原始素材正文）
========== source 到上一行结束 ==========
```

抬头必须写清**期望**，因为 `nodes/prd-score-node.py` 按 `EXPECT[fixture 名]` 取期望打分；抬头文字是给人看的对照说明，`EXPECT` 是给机器看的。

## 建议覆盖的样本

| 编号 | 类型 | 用途 |
|---|---|---|
| F1 | 真实感素材 | 正常路径：多条反馈 → 多条需求 |
| F2 | 空素材 | 空输入日，应输出「无有效需求」而非编造 |
| F3 | 矛盾需求 | 两条反馈互相冲突，应显式标注冲突而非二选一 |
| F4 | 单一需求 | 只有一条需求，检查不硬凑条数 |
| F5 | 含禁用空话素材 | 素材里本身就有「提升效率」这类表述，检查是否被原样搬进 PRD |
| F6 | 超长素材 | 检查抽取是否遗漏、去重是否失效 |

## 隐私

全部样本必须虚构。真实用户反馈、真实姓名、真实联系方式不得进入本目录。
