## 2026-10-14 ｜ 金标准 PRD（F1）｜ 外部独立评审发现 3 处缺陷，其中 1 处说明规则本身有洞

- **现象**：把金标准 PRD 交给外部独立评审（Hark）挑错，指出三处问题：
  1. R2 验收标准写「抽检 100% 可读」——**这正是本项目要防的废条**
  2. 成功指标「公式求助平均耗时」的观测方式填「埋点」，但**求助发生在产品外，埋点测不到**
  3. 「上线与验证计划」写了范围与阈值，**没写灰度跑多久**

- **复现率**：单次评审即全部指出，三条都不是随机波动（属于结构性缺陷，每次都存在）。

- **是否误导读者**：是。尤其第 1 条——「100% 可读」会让评审者误以为该指标已可验收。

- **定位过程**：先查代码节点，发现 `prd-hard-rule-node.py` 的 H3（验收标准可测量）**只检查「是否含数字或判定词」，不检查「数字背后的判据是否客观可判定」**。「100%可读」因为含 `100%` 而被 H3 放行。**问题不在 PRD，在规则：规则声明了目标（可测量），实现只抓了表层特征（有数字）。**

- **结论**：修改（三条都改，且优先改规则而非改文案——否则同类问题下次还会漏）。

- **修法**：
  - 新增 **H9 验收标准须客观可判定**：命中主观词表（可读 / 好用 / 易用 / 清晰 / 流畅 / 友好 / 智能 / 高效 / 美观 / 稳定 / 顺畅 / 直观 / 合理）即打回。
  - 新增 **H10 上线计划须含灰度时长**：`上线与验证计划` 章节须匹配 `数字 + 周/天/日/个月/月/小时`。
  - 新增 **S5 指标与观测方式是否匹配**（LLM 判定）：声称埋点但指标发生在产品外，判低分。
  - 修金标准 PRD：R1/R2 验收标准改为可自动校验或有人工流程与阈值的写法；观测方式区分「埋点」与「月度访谈（因指标发生在产品外）」；灰度补「2 周 + 两次决策时点」。

- **修复后**：金标准 PRD 仍对 F1 得 8/8；新增 4 项断言覆盖 H9/H10 的正反用例，全部通过。

- **这条记录要记住的事**：**循环验证证明不了规则正确。** 我写的 PRD 过我自己写的 rubric，只说明规则可达，不说明规则对。引入外部评审一次就戳穿了——而戳穿的不是文案，是规则。**外部评审不是可选项，是这套方法的必要环节。**
